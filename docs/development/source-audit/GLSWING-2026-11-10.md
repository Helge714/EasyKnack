## Independent reconstruction

1. Clone the clean Core commit locally and run JDK 25 / Maven 3.9.11:
   `mvn -pl glswing-core -am -Dglswing.test.gl=true install`.
   All 171 tests pass, with no failures, errors or skips.
2. Freeze the resulting artifacts; extract the captured build-input ZIP into a
   separate directory. An empty Git repository prevents the extracted source
   build from accidentally inheriting EasyKnack's surrounding Git identity.
3. Rebuild from the extracted files using
   `mvn -pl glswing-core -am -DskipTests package`.
   Tests are omitted only for this second correspondence build.
4. Compare with `scripts/compare-jar-content.py`. All 962 class files and every
   other runtime resource match byte for byte. The sole differing entry is
   `META-INF/glswing/build.properties`, containing generated build/Git identity.
   The complete JARs are not claimed to be byte-reproducible.

The matching candidate runtime/sources are installed in the local Maven cache;
the reviewed build-input ZIP is also available at its locked local Maven path.
Future SNAPSHOT rebuilds will change package identities and hashes. They must not
silently replace this frozen candidate: either restore the reviewed bytes for
packaging or review and freeze a new candidate.
